Git 进阶：rebase、cherry-pick 与 worktree

用过 git merge 之后，仓库里常常混着一堆「Merge branch 'xxx'」的合并提交，历史又长又乱。本文整理三个我几乎每天都在用的进阶命令：rebase、cherry-pick、worktree，并给出一些避坑经验。

一、交互式 rebase：整理你的提交历史

交互式 rebase 允许你在合并前重新排列、合并、修改、删除提交。基本用法：

git rebase -i HEAD~5

编辑器里会出现最近 5 个提交，每行对应一个指令：

pick  a1b2c3d feat: 新增登录接口
pick  e4f5g6h fix: 修正 token 过期判断
pick  i7j8k9l docs: 补充 README
pick  m0n1o2p chore: 清理无用变量
pick  q3r4s5t test: 补充单元测试

常用指令

  • pick：保留提交
  • drop / 删除整行：丢弃该提交
  • squash：把该提交合并到前一个，适合「一个功能多个小提交」的场景
  • reword：保留提交但改 commit message
  • edit：停下来在该提交处暂停，可以拆分或改代码

黄金法则： 永远不要对「已经推到远端、且他人可能已基于其开发」的提交做 rebase。否则协作者的本地历史会和你不一致，pull 时产生混乱。本地未共享的分支随便整理。

把多个提交压成一个

git rebase -i main
# 把想合并的提交都改成 squash（第一个保留 pick）
# 保存后依次弹出编辑器填写合并后的 commit message

二、cherry-pick：把别的分支上的某个提交拿过来

场景：一个 hotfix 提交只存在于 release 分支，你需要单独把这一个改动应用到 main，而不想整支合并。

git checkout main
git cherry-pick a1b2c3d

一次挑多个提交、或者跨一段区间：

git cherry-pick a1b2c3d e4f5g6h
git cherry-pick main..feature-x    # feature-x 上但 main 没有的提交

遇到冲突时：

git cherry-pick --abort       # 放弃整个 pick
git cherry-pick --continue    # 解决冲突后继续
git cherry-pick --skip        # 跳过当前提交

--no-commit 技巧

只想拿提交的内容、不想保留它的 message：

git cherry-pick --no-commit a1b2c3d
git commit -m "我自己的描述"

三、worktree：多分支并行开发不互相打扰

传统流程：要切分支前，得先把当前工作区清理干净（commit 或 stash），切过去再切回来。worktree 让你把同一个仓库的多个分支同时展开在磁盘上不同的目录，互不影响。

# 把 hotfix 分支展开到 ../worktrees/hotfix 目录
git worktree add ../worktrees/hotfix hotfix

# 查看所有 worktree
git worktree list

# 不再需要时移除
git worktree remove ../worktrees/hotfix

典型用法：当前目录继续开发 feature，同时用另一个 worktree 目录快速处理 hotfix，不需要切换工作区、不需要 stash。每个 worktree 有独立的 index 和工作区，但共享同一个 .git 对象库，磁盘占用很小。

注意

  • 同一个分支不能同时被两个 worktree 检出。
  • 用 git worktree remove 删除，不要直接 rm -rf（会留下孤儿目录记录）。

四、速查表

需求命令
整理本地提交历史git rebase -i main
把单提交摘到别的分支git cherry-pick <sha>
多分支并行git worktree add <dir> <branch>
撤销一次提交（保留改动）git reset HEAD~1
撤销一次提交（也撤改动）git reset --hard HEAD~1

五、小结

rebase 负责「让历史好看」，cherry-pick 负责「精准搬运改动」，worktree 负责「多任务并行」。三者配合，基本能覆盖日常协作里的所有分支管理需求。
